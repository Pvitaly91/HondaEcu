# M2k — native fuel calculation after DATA0140

The bounded read-only chain is complete: native fuel lookup → word store at
`134E` → same-machine word read at `21DB` → unsigned arithmetic → native
`A/er2` result at `21F1`, stopping **before `21F2`**. The immediate software
consumer is `21F2 XCHG A,er3` (static-only), using the identical A value
retained by the native er2 store. A later conditional `er2` load is `227A`;
unchanged original ROM60F8=0 bypasses that reload. The result is a raw
scaled/saturated fuel component, not final pulse width, milliseconds, fuel
quantity, AFR, dead time, or electrical injector output. Physical scale is unknown.
Strict M2i remains **Blocked** on its own `47 81` dependency.

## Path selection and static limits

Both leads were compared against the unchanged exact original and matching
private listing. Scoped private source audit matched 229 instruction boundaries
and their bytes; no listing, ROM, full map, binding or actual trace is published.

The first lead, `14ED/14F0`, does read a word at `0140`, but mandatory local
predecessor `14D6` first stores a **byte** there. It replaces the low byte of the
lookup generation. Entry gate `14CA` requires `DATA011F.5=1`; `14D0..14E6`
uses software inputs `00D9/00BC`, table helpers and a detour through `7904`.
`DATA0164/0165` are byte lookup results; `14E8/14EB` produce their unsigned
byte product in A. `14ED` loads the now partially overwritten word into er0,
then `14F0` produces a 32-bit unsigned product in `er1:A`, independent of DD.
`14F2` sets word DD; `14F4..14FC` shift/rotate/narrow with carry-overflow
branches, followed by `0142/0144` additions, a conditional two-bit reduction
using `00B7.0`, and the `012A.1` clear branch. Native stores `151A/151E`
target `03A2/03B4`; helper `5991` subsequently transforms the software value
before additional channel stores. This is a separate static lead, **NotRun**,
not an original-lookup DATA0140 handoff. Its entire mandatory form inventory
and helper/caller state are not admitted as a second runnable contract.

`21DB/21E0` instead loads the original lookup word before any overwrite. Its
local closed fragment needs no inherited arithmetic accumulator, CF, er0,
er1, er3, X1, X2 or DP value: both multiply operands are loaded natively,
and the needed carry is generated by the local high-word shift. The preceding
`2194..21DA` creates a **different additive correction** in er3/X2, not an
operand consumed before this fragment's exit; that producer is NotRun.
Static caller `217A` enters this earlier correction path if `DATA0124.4=0`;
the opposite branch clears channel words and bypasses it. M2k clears only that
mask once, preserving neighbouring bits, for caller compatibility. The gate
itself and additive correction are **not executed or claimed recovered**.
Neither this gate nor the selected fragment depends on `DATA0127.1`, so both
once-initialized map contexts are compatible. Other upstream gates are outside
the isolated entry, not silently switched between stages.

At `1350` the original continuation reads `DATA0182`, branches on
`011F.5/012C.4`, and requires additional unproduced fields, helper paths and
later peripheral accesses. The existing bounded prefix does not establish a
continuous recovered path to `21DB`. M2k therefore discloses a **scripted
1350→21DB jump**; it does not claim ECU main-loop scheduling or caller recovery.

After `21F1`, `21F2` exchanges the accumulator with er3 and calls a signed
additive-correction helper via VCAL4. Later `03A2/03B4` stores and the per-channel
loop follow additional gates. `227A` specifically reloads the still-preserved
er2 word; `227B` can bypass per-channel multiplication, otherwise `2280..228A`
loads a table byte, multiplies, shifts and saturates. `228D..2295` applies the
er3/X2 correction and stores through DP. `226F/2273` also gates whether that
loop runs: original ROM60F8=0 takes the bypass to229F, so227A is not claimed
reachable in the unchanged original continuation. Immediate21F2/VCAL4 instead
consumes the live A component and additive correction; that consumer is also
static-only. The helpers5958..596A and5991..59A5 preserve er2; this is a static
lifetime check, not execution. These consumers are not native coverage of
timers, IRQs, scheduling values, or an electrical driver.

## Exact integer arithmetic and primary ISA evidence

For `source=u16(DATA0140)` and `factor=u16(DATA0158)`:

1. Native L/MOV load A/er0 in that order. MUL writes low16 to A, high16 to er1.
2. SRL er1 exports its bit0 to CF; ROR A consumes that CF, producing product>>1.
3. LB A,r2 replaces AL with the shifted-high low byte and sets DD=0, retaining AH.
4. L A,ACC reads the **word CPU alias at0006**, sets DD=1; SWAP exchanges bytes.
   The resulting A is `(product>>9)&FFFF`, not simply high16.
5. CMPB r3,#0 compares the shifted-high upper byte. JEQ accepts equality zero;
   otherwise L A,#FFFF saturates. ST A,er2 produces the native software result.

Thus the observable result is `min((u32(source)*u32(factor)) >> 9, 65535)`.
Saturation is exactly `product >= 2^25`; this is narrowing derived from the
operations, **not** an asserted fixed-point physical scale or unity coefficient.
There is no division instruction, divisor-zero rule, or floating-point shortcut.
Ordered banked word writes are factor→0100, high16→0102, shifted high→0102,
result→0104, with identical result retained in A. Carry, DD, comparison operands/ZF, saturation branch, bank aliases,
stack, extents and final value are compared, not merely the product.

Primary source: OKI *MSM66201 Instruction Manual*, first edition September1991,
the previously obtained private source, visually read after PDF rendering.
Printed pages3-69/70 (L/LB),3-83 (word MOV erN,obj),3-100 (MUL),3-121 (ROR A),
3-151 (SRL obj),3-164 (word SWAP),3-42 (CMPB),3-66 (JEQ),3-154 (ST).
Exact admission checks mnemonic, byte-pattern length, DD and addressing; the
generic direct L is additionally restricted to ACC alias0006. MOV/MUL/SRL
preserve DD; ROR/SWAP/ST require word DD, L sets it and LB clears it. MUL changes
ZF, preserving CF/HC; SRL/ROR change CF; CMPB produces the consumed ZF/CF/HC.
No47 81,45 81 or disputed SUBB permission is admitted. No decoder/executor
arithmetic semantic fix was required. The shared bus gained opt-in observation
with a partial-store/fault regression; synthetic execution gained already
primary-established MUL for the new invented subprocess test.

Runner0.19.0 advertises `fuelCalculationChain`;0.18.0 lacks it and is rejected
for this operation.0.18.0 remains compatible for historical operations,
including the unchanged M2j correction evidence contract. Version metadata is
not executable attestation or independent ISA proof.
