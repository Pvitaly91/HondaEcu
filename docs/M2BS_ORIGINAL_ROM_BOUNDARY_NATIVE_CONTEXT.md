# M2bs - original ROM boundaries and native context, research only

M2bs adds a bounded **read-only** verifier, not a firmware loader, emulator,
original-ROM execution operation, patcher or hardware interface. It connects a
privately selected historical candidate's actual instruction bytes with frozen
listing extents, independent instruction recognition, reviewed manufacturer
semantics, the M2av IR and selected historical source-CPU observations.

The parent is M2br commit `2657bb8ae3add410e693d988bac7ccf5cece7f50`. M2br's
5470 three-stage executions / 84724 retirements, independent oracle, exact-SHA
CI and 24 full-byte comparisons remain historical evidence at that identity.
M2bs does not rerun them locally or promote synthetic tickets into a native
caller, original stack frame or ECU scheduler.

## Source selection and evidence domains

The original candidate must be supplied by an explicit **local private path**.
Its entire size and SHA-256 must match the separately selected historical M1
baseline binding and provenance dossier. The frozen listing is independently
bound and its selected extents must equal the bytes actually read from that
candidate. A filename, a 32768-byte size, a similar image or matching synthetic
M2bj emission is not a source identity. No ROM is downloaded, repaired, padded,
modified or written back. Archive continuity does not establish factory origin,
ECU custody, revision authenticity or permission to redistribute firmware.

The private profile names exact local source bindings (path, byte count, SHA-256):
baseline binding, provenance dossier, frozen listing, two selected historical
native reports, their two original-ROM-bound C# reports and their previously
sealed independent verification proof. Both C# ROM identities must equal the
verified current candidate digest; all 15 complete raw checkpoint objects are
joined to the reports without field exclusions. No new CPU or C# run is used.
This is caller-reviewed evidence selection, not a signed manufacturer profile or
automatic factory-ROM identification. Unknown source identity is refused.

UNC/URL input is refused before opening: restore only the explicitly needed
historical data through the private archive workflow first. The verifier never
probes a NAS, polls it, searches the disk or obtains credentials. Missing local
data is a real refusal, not an invitation to substitute an invented fixture.

Evidence categories stay distinct:

| Category | Meaning |
|---|---|
| ObservedNative | Qualified historical source-CPU/Bus observation, with selected actual bytes, field locators and an independently verified historical relationship; not physical ECU execution |
| StaticRomDerived | Actual ROM boundary/documentary semantics or a transparently derived architectural relationship; not a new runtime value |
| HistoricalReplay | A previous offline model/reconstructed snapshot; not a native generation |
| SyntheticOnly | Invented M2bn-M2br or test-only evidence; no native ownership |
| Unknown | No sufficient selected evidence; never silently zero/false |

A current reconciliation of old observation files is not a new native execution.
An in-memory receipt produced after checking their actual relationships is
explicitly labeled a new derived verification receipt, not an old runtime file.
Historical machine IDs and scratch-sequence groupings are not OS PIDs, process
UUIDs or hardware identities. No such missing identity is manufactured.

## Bounded inventory and independent expectations

The public contract specifies 27 native instruction extents / 24 forms / 67
selected bytes. Eighteen original algorithm sites account for 45 bytes. The
other nine are the producer store, six predecessor instructions and the first
instruction at each peripheral continuation. This is not a whole-ROM
disassembly or a claim that every byte between the two arms is executable code.

The 18-site expectations are taken from the unchanged reviewed M2av IR and M2bf
static site inventory. The nine context expectations come from independently
reviewed manufacturer code cells and historical source context. They are not
generated by the new decoder or by production Rust output. Recognition of the
15 original forms reuses the unchanged independent M2bc recognizer; the scoped
wrapper and nine additional context forms do not change production decoding.

For each selected extent the verifier checks PC, exact length, permitted DD
interpretations, typed operands, ordered control-flow successors, functional
DATA reads/writes, functional flag reads/writes and DD selection dependencies.
DD selection is not confused with a functional carry/zero dependency.
PROGRAM instruction bytes are not DATA operand reads.

Manufacturer authority is the OKI MSM66201 Instruction Manual, first edition,
September 1991, SHA-256
`f6e423ac0bd15378754e30c35ed426415ec219e360c68e817ab451df72142271`.
New full-page visual checks cover JBR (3-64), JC/NE and signed displacement
(3-66/67), L (3-69), LB (3-70), MOVB rN (3-99), ST/STB (3-154/155),
ANDB obj,A (3-25), ORB obj,A (3-108), and CMPB obj,#N8 (3-42).
Printed labels, rather than a presumed universal PDF page offset, identify the
semantics; duplicate/misaligned scanned pages are not silently renumbered.
Earlier 18-site manufacturer reviews remain separate retained authority.
No JGT/C8 conflict, customer ASIC identification, reset or peripheral side
effect is resolved by this limited review.

## Entry and predecessor context

The selected predecessor window has these documentary effects:

| PC | Form / effect | Successors |
|---|---|---|
| 54F5 | JBR current-page 0128.2; no flag writer | 5533 or 54F8 |
| 54F8 | MOVB local r0, immediate FF; flags retained | 54FA |
| 54FA | Word L A,DATA0196; sets DD1 and ZF | 54FC |
| 54FC | Word ST A,er1; requires DD1, flags retained | 54FD |
| 54FD | CMPB DATA0117 against immediate 0F; CF/ZF only | 5501 |
| 5501 | JNE consumes ZF0; flags retained | 556F or 5503 |
| 556F | LB A,DATA018E; updates AL/ZF, clears DD, retains AH | 5571 |

Entry556F is a basic-block entry, not a proved C function or CAL/RT frame.
Incoming DD0 and DD1 are both valid for the first LB. The following
DD-sensitive byte forms require the DD0 it establishes. In particular a
DD-sensitive store byte pattern under DD1 is a word ST, not a decoder failure
that can be ignored; the verifier compares the expected form and width.

LRB0021 is the conditional reviewed context: page0100, local bank0108..010F.
SCB is derived from the observed PSW low three bits. Aliases and all other
pointing banks retain their separate obligations. The historical PC-only
05ED-to54F5 seam is an explicit harness schedule, not recovered firmware
scheduling or a real call frame. The JNE alternate can reach556F without
executing the timer instructions at5503; no universal timer precondition or
global entry dominance is inferred. Other static incoming edges and indirect
aliases outside this selected scope remain separate research questions.

## Original algorithm and stop-before continuations

The unchanged 18-site algorithm has four static paths, with original native
instruction counts 10/12/13/15. Its word comparison at5578 reads little-endian
DATA0196/0197 against **code-owned immediate00C0**, not DATA00C0. JLT consumes
unsigned-borrow CF. The first gate012A.7 short-circuits the second0124.5.
Same-value writes are retained as generation events, not deduplicated stores.

| Path | Predicate within this bounded software model | Stop before | Ordered writer PCs |
|---|---|---|---|
| A | Word0196 below00C0 | 55C5 | 5572,55C1,55C3 |
| B | NotBelow;012A.7 set | 5596 | 5572,557F,5582 |
| C | NotBelow; first gate clear;0124.5 set | 5596 | 5572,557F,5582 |
| D | NotBelow; both gate bits clear | 5596 | 5572,557F,5582,558B,558E |

Static four-path coverage is not four historical native witnesses. In
particular path C still has no witness in the selected historical corpus.

Both original continuation boundaries are decoded **without execution**:

| PC | First original instruction | Minimum additional live-in / access |
|---|---|---|
| 5596 | ANDB P2,A; three-byte zero-page byte RMW | Actual AL and existing DATA/SFR0024/P2 value; read and write ownership |
| 55C5 | ORB P2,A; three-byte zero-page byte RMW | Actual AL and existing DATA/SFR0024/P2 value; read and write ownership |

Both forms are DD-independent and document ZF modification. No P2 value,
peripheral read-clear/latch behavior, physical output, timing or board mapping
is established by decoding them. P2 is not assigned 00/FF, mocked or replaced by
a synthetic sink. Wider downstream timers, IRQ state, stack/frame safety and
real rejoin are not executed or admitted by this verifier.

## DATA0196 and complete context matrix

Selected historical journals reconcile a native word store at05EB with actual
54FA and5578 word reads on the same recorded machine and source-sequence group.
The generation identity retains event index, all-native-write ordinal and
value. All intervening functional writes are checked for overlap; equal-value
stores are still distinct. A ready word copied or seeded by the host cannot
manufacture the missing generation. Explicit other writer/reader leads and
unmodeled indirect/indexed/stack aliases do not become globally absent merely
because the selected journal has no overlap.

The matrix covers 77 fields, including PC/A/AL/AH, CF/ZF/HC/DD/full PSW/OtherPSW,
LRB/SCB/SSP, X1/X2/DP/USP, all 32 pointing-bank aliases, r0..r7/er0..er3,
DATA0117/0124/0128/012A/018E/018F/0196/0197, SF, P2, downstream SFR,
native frame, interrupt/peripheral context and scheduler. It preserves multiple
source/generation observations instead of assigning one fabricated global state.

Only actually serialized fields may be ObservedNative. AL/AH/flags/SCB and local
word aliases derived from snapshots carry transparent derivation provenance.
Before-prefix RAM is not mislabeled entry RAM if intervening instructions can
write it. An observed technical SSP value does not prove an available native
frame, reset state or stack ownership. SF storage/meaning, unseen banks, actual
peripheral ownership and native scheduling remain Unknown as appropriate.

The previously sealed 42 completed observations are 33 original-image strict
quartet-derived cases, six separately classified in-memory B-image cases and
three original-image gate controls. They are not 42 new original-ROM runs.
M2bs freshly reconciles the selected original-image A/B/D representatives;
its report separates that selected scope from the inherited 42-case proof.

## Executable local verifier and public synthetic regressions

Run from the repository root with existing Python dependencies:

```text
python -B research/p28-word0196/validate_original_rom_boundary.py
  --rom <explicit-local-private-candidate>
  --profile <explicit-local-private-source-bindings.json>
  --output <fresh-private-evidence.json>
  --public-output <optional-fresh-public-safe-summary.json>
```

The entire input is opened only as `rb`. Complete before/after byte and file
identity fences detect mutation or equal-byte path replacement. Existing
outputs and input/output aliases, including hardlinks, are refused. Outputs
must be fresh JSON evidence, never BIN/HEX/object data. Public summary excludes
private paths, whole-ROM identity, OEM bytes and private register values.

Public regression command:

```text
python -B -m unittest discover -s research/p28-word0196/original_rom_boundary -p '*_tests.py'
```

Fixtures are independently invented; they do not contain the candidate, its
native byte sequence or original report snapshots. Tests distinguish altered
bytes/operands, boundaries/DD/flags, wrong source/profile, truncation, mutation,
unavailable local/NAS source, malformed or promoted evidence, fabricated native
paths/frames/SF/peripheral assumptions, writer ordinals, overlap and output
overwrite. A failed original-ROM identity check is never repaired by accepting
a synthetic fixture. No test executes any target instruction stream.

## CI and frozen historical inputs

Original ROM verification is **local-only**. Public CI is
`PublicSyntheticValidatorRegression`; it cannot claim
`LocalOriginalRomReadOnlyVerification` without the private candidate and sources.
No ROM, private report, manufacturer scan or OEM listing is uploaded.

M2br's immutable validators intentionally require a closed source membership.
Adding M2bs files to that active tree would invalidate those historical source
assumptions. They are not rewritten or weakened. The matrix therefore first
checks out exact M2br2657, runs every existing historical build/test/format and
artifact step unchanged, then switches the **same** checkout to the exact active
M2bs SHA with `clean:false`. Active M2bs source integrity and invented negative
tests run after that switch. No repository, cache or worktree copy is needed.
The Desktop Windows job remains byte-identical and uses its ordinary active
checkout. All three main jobs remain required.

The active source guard compares raw Git blobs/modes of every baseline source:
only the explicitly checked workflow orchestration delta and the closed new
M2bs file set are allowed. Thus retained compiled QA has byte-identical
production inputs; it is explicitly historical-source QA plus input equality,
not a newly claimed execution of altered production code. Historical M2br
canonical artifacts retain source2657 even when their enclosing new CI run has
an M2bs head SHA. They are not misrepresented as M2bs native evidence or passed
to the old exact-SHA M2br delivery consumer for a new acceptance claim.
